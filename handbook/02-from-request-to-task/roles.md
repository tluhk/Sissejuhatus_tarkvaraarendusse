# Rollid

**Märge:** Seminaris

Arendusotsus võib olla tehniliselt teostatav, aga kasutajale kasutu või tellijale liiga kallis. Erinevad rollid aitavad sellised küsimused õigel ajal esile tuua. **Roll** näitab, kes mille eest vastutab ja kelle vaatenurka otsuses arvestatakse.

Roll ei ole alati ametikoht. Väikeses meeskonnas täidab üks inimene mitut rolli, suures ettevõttes võib ühe rolliga tegeleda terve meeskond.

## Levinud rollid

| Roll | Peamine vastutus |
|---|---|
| **Tellija** (*client*) | selgitab, miks muutust vaja on, ning seab eelarve ja piirangud |
| **Tooteomanik** (*product owner*) | hoiab fookuses toote väärtust ja järjestab tööd tähtsuse järgi |
| **Projektijuht** (*project manager*) | korraldab ajakava, vastutajad ja sõltuvused |
| **Analüütik** (*business / system analyst*) | uurib vajadusi ja reegleid ning täpsustab, mida süsteem peab tegema |
| **UX-uurija ja -disainer** (*UX researcher / designer*) | uurib kasutajaid ja kavandab, kuidas nad süsteemi kasutavad |
| **Tarkvaraarhitekt** (*software architect*) | kavandab süsteemi suuremad osad ja nende seosed |
| **Arendaja** (*developer*) | teostab muudatused ja parandab vigu |
| **Testija** (*tester, QA*) | muudab ootused kontrollitavaks ja kontrollib tulemust |
| **Käituse eest vastutaja** (*operations, DevOps*) | avaldab tarkvara, jälgib selle tööd ja hoiab seda töökorras |

## Rollid töötavad koos

Rollid ei tööta järjest, vaid üheskoos. Arendaja võib juba uurimise ajal märgata tehnilist piirangut. Testija aitab sõnastada, mille järgi hiljem tulemust kontrollida. Kvaliteedi eest vastutab kogu meeskond, mitte ainult testija.

## Rollid kursuse meeskonnas

Meeskond lepib igas etapis kokku, kes hoiab millist vaatenurka, näiteks uurija, analüütik, töö korraldaja ja tulemuse kontrollija. Olulised otsused arutatakse läbi kogu meeskonnaga.

Üks liige on lisaks **release manager**: ta koondab etapi tulemuse avaldatud versiooniks. Rollid vahetuvad etappide vahel, et igaüks kogeks erinevat vastutust.
